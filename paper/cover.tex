\textbf{Re: Submission to \textit{Computer Standards \& Interfaces}}\\
\textbf{``A Machine-Readable Standards-Traceability Framework for Cybersecurity Risk Evidence in IoT Environments''}

Please consider the following manuscript for publication as an original research article in \textit{Computer Standards \& Interfaces}:
\begin{quote}
\textbf{``A Machine-Readable Standards-Traceability Framework for Cybersecurity Risk Evidence in IoT Environments''}
\end{quote}

\textbf{Scope fit.} The manuscript presents a machine-readable standards-traceability artifact for cybersecurity risk evidence that combines a UML/XMI representation, a Goal--Question--Metric validation layer, and standards-linked downstream decision support. Its primary emphasis is on the specification, validation, and application of standards-aligned representations and interoperable evidence mappings for information-security workflows, which fits the journal's focus on standards, interfaces, information management, and applied methods.

\textbf{Main contributions.}
\begin{itemize}[leftmargin=*, nosep]
  \item A machine-readable UML/XMI and GQM artifact covering \textbf{93/93} ISO/IEC 27001:2022 Annex A controls and \textbf{106/106} NIST CSF 2.0 subcategories, together with validator scripts and logs.
  \item A standards-traceable quantitative risk formulation based on AV$\times$EP$\times$IL with explicit provenance for CVSS, asset-value, and optional human-factor inputs.
  \item A telemetry-only IDS evidence-generation path that excludes downstream enrichment fields from the classifier feature set and uses boundary-safe train/validation/test partitioning on the public CIC IoT 2023 profile.
  \item A Gordon--Loeb-bounded portfolio comparison layer that exposes explicit cost-risk trade-offs while preserving links back to controls, metrics, and represented evidence objects.
\end{itemize}

\textbf{Reported empirical results.} On the strict public CIC IoT 2023 profile reported in the manuscript, the artifact-default scorer achieves \textbf{F1 = 0.995}, \textbf{AUROC = 0.997}, \textbf{PR-AUC = 1.000}, and \textbf{Brier = 0.006}. At the operating point selected on the pre-test window for a nominal 1\% FPR target, the hold-out test window reports approximately \textbf{98.2\%} detection rate at \textbf{0.44\%} realized FPR. On the optimization side, NSGA-II returns a \textbf{61}-point frontier (HV=\textbf{31,436.9}), Greedy returns a \textbf{14}-point prefix frontier (HV=\textbf{30,810.2}), and Exact-ILP returns a \textbf{16}-point frontier (HV=\textbf{28,970.3}). The artifact-default NSGA-II selection yields \textbf{4.5\%} lower residual risk at \textbf{5.0\%} higher three-year control-side TCO than the matched-budget Greedy comparator, making the trade-off explicit.

\textbf{Reproducibility and limitations.} The submission includes code, schema artifacts, mappings, and validator outputs. Public source and manuscript materials are available through the project repository at \href{https://github.com/ErcanErkalkan/AI_Enabled__Standards_Aligned_Security_Risk_Management}{GitHub}. The manuscript is explicit about the main public-data limitations: victim/device IDs are not exposed in the public CIC IoT 2023 CSV rows, asset values are telemetry proxies rather than enterprise register values, and the ordered hold-out in the merged CSV release remains a surrogate for true wall-clock chronology because row-level timestamps are absent.

\textbf{Submission package.} The manuscript is accompanied by a separate highlights file and a separate graphical abstract file, aligned with the current \textit{Computer Standards \& Interfaces} Guide for Authors.
